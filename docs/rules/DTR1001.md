# DTR1001: Avoid creating HttpClient per operation

| Property           | Value       |
| ------------------ | ----------- |
| Category           | Reliability |
| Default severity   | Warning     |
| Confidence         | High        |
| Enabled by default | Yes         |

## Cause

An `HttpClient` instance is created inside a method, local function,
accessor, or anonymous function.

## Why this matters

Frequently creating and disposing `HttpClient` instances can cause
connection churn and socket exhaustion.

Use `IHttpClientFactory` in applications that use dependency injection,
or reuse a long-lived `HttpClient` instance.

## Noncompliant code

```csharp
public async Task<string> GetWeatherAsync()
{
    using var client = new HttpClient();

    return await client.GetStringAsync("/weather");
}
```

## Compliant code

```csharp
public sealed class WeatherService
{
    private readonly HttpClient _client;

    public WeatherService(HttpClient client)
    {
        _client = client;
    }

    public Task<string> GetWeatherAsync()
    {
        return _client.GetStringAsync("/weather");
    }
}
```

Registration:

```csharp
services.AddHttpClient<WeatherService>();
```

## Configuration

```json
{
  "rules": {
    "DTR1001": {
      "enabled": true,
      "severity": "warning"
    }
  }
}
```

## Limitations

The current implementation reports creation in executable code. It
does not report static or instance field initializers because those
instances may intentionally be long-lived.
