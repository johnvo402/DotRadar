# DTR1101: Avoid blocking on asynchronous operations

| Property           | Value       |
| ------------------ | ----------- |
| Category           | Reliability |
| Default severity   | Warning     |
| Enabled by default | Yes         |

## Cause

A .NET asynchronous operation is synchronously blocked using one of
the following patterns:

```csharp
task.Result;
task.Wait();
task.GetAwaiter().GetResult();
```

## Why this matters

Synchronously blocking a `Task` occupies the current thread while the
operation is incomplete. In server applications this can reduce
throughput, cause thread-pool starvation, and make deadlocks more
likely.

## Noncompliant code

```csharp
public Order GetOrder()
{
    var task = repository.GetOrderAsync();
    return task.Result;
}
```

```csharp
public void Refresh()
{
    cache.RefreshAsync().Wait();
}
```

## Compliant code

```csharp
public async Task<Order> GetOrderAsync(
    CancellationToken cancellationToken)
{
    return await repository.GetOrderAsync(
        cancellationToken);
}
```

## Configuration

```json
{
  "rules": {
    "DTR1101": {
      "enabled": true,
      "severity": "error"
    }
  }
}
```

## Limitations

DotRadar currently recognizes standard .NET `Task`, `Task<T>`,
`ValueTask<T>` and their awaiter types. A custom task-like type may
not be recognized.
