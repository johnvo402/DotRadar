# DTR1102: CancellationToken parameter is not used

| Property           | Value       |
| ------------------ | ----------- |
| Category           | Reliability |
| Default severity   | Warning     |
| Enabled by default | Yes         |

## Cause

A method declares a `CancellationToken` parameter but does not use
that parameter anywhere in its executable body.

## Why this matters

Callers expect an operation accepting `CancellationToken` to support
cooperative cancellation. Ignoring the token can cause unnecessary
work to continue after a request, job, or application is cancelled.

## Noncompliant code

```csharp
public async Task GenerateReportAsync(
    CancellationToken cancellationToken)
{
    await Task.Delay(1000);
}
```

## Compliant code

```csharp
public async Task GenerateReportAsync(
    CancellationToken cancellationToken)
{
    await Task.Delay(
        1000,
        cancellationToken);
}
```

The token may also be checked directly:

```csharp
public Task ProcessAsync(
    CancellationToken cancellationToken)
{
    cancellationToken.ThrowIfCancellationRequested();

    return ProcessCoreAsync();
}
```

## Configuration

```json
{
  "rules": {
    "DTR1102": {
      "enabled": true,
      "severity": "warning"
    }
  }
}
```

## Limitations

The current implementation considers any semantic use of the
parameter valid. It does not yet prove that the token reaches every
cancellable asynchronous operation.
